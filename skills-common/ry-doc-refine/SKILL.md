# 文档表达优化

把已经形成的意图、事实和边界重新编译成目标读者能够准确理解、自然使用并继续维护的文档。旧稿提供语义证据，不构成叙事基线；可以跳出原有章节、背景铺陈和对象模型，从当前认识重新完成表达。

本 Skill 可以独立完成审阅和修改，不依赖其他设计或治理 Skill。优化不是统一文风或缩短篇幅，也不是每份文档必须经过的门禁；只有修改能降低读者不必要的组织、拼接和推断负担时才实施。

## 确定任务与权限

| 用户请求 | 默认结果 |
|---|---|
| 审阅、评价或提出建议 | 给出判断和建议，不修改文件 |
| 优化、整理、重构或重写 | 在指定范围内修改并复核 |
| 局部调整 | 只处理指定内容及保持整体一致所需的直接相邻部分 |

普通润色、文档内部结构调整、叙事重建、去重和必要语境补全属于优化授权，无需逐项确认。新的事实、目标、职责、行为、授权或完成条件属于契约选择：可以主动提出，但在用户确认前不写成当前规则。用户当前请求已经明确提供新目标或授权某类变化时，该决定已经成立，不重复索要批准。

不要把一份文档的请求自动扩大为整个工作区治理。发现跨文件问题时可以指出；只有当前授权覆盖文档集时才重组文件关系。

## 文档契约与读者

编辑前先建立当前文档契约：

- 文档承担什么职责，什么不属于它；
- 目标读者是谁，实际能够看见哪些上下文；
- 读者需要形成什么理解、行动或体验；
- 哪些事实、意图和关键契约已经确认，哪些仍是推断或未决选择；
- 当前产物是正式正文、设计稿、未完成草稿还是可实例化模板；
- 哪些语气、节奏和形式本身就在承担文档功能。

不能用编辑者拥有的对话记忆替文档补全含义，也不要求文档脱离真实环境完全自足。判断基准是目标读者实际可见的世界。

只加载与当前文档职责匹配的类型参考：

- 优化 `SKILL.md`、Skill references 或完整 Skill 文档包时，读取 [Skill 文档表达](references/types/skill-expression.md)；
- 优化 `soul.md`、人格模块或以人格生成与关系体验为核心的身份文档时，读取 [Soul 文档表达](references/types/soul-expression.md)；
- 混合文档可以组合相关视角；没有匹配类型时，仅使用本文件的全局方法。

文件名只是路由线索。类型参考补充特有判断，不覆盖用户意图、目标环境事实和本文件的协作边界。

## 语义保真

保真维护的是已确认意图和关键契约，不是旧措辞、旧章节或旧叙事。可以重新解释背景、重建对象心智、增删必要内容并整体重写，只要没有把文档带向另一个目标或未经确认地改变读者行为。

区分三种内容：

| 层级 | 优化权限 |
|---|---|
| 意图主轴：目标、用途、受众、核心价值和关键取舍 | 重新理解和表达，不静默替换 |
| 关键契约：职责、触发、输入输出、授权、行为边界、外部影响和完成条件 | 主动检查并提出重组；新选择确认后实施 |
| 叙事编译：对象模型、背景组织、认知入口、章节、措辞、理由和示例 | 在当前授权内自主重构 |

补充内容时，可以直接写入从已确认事实和目标可靠推出、且为读者正确理解所必需的语境。存在多个同样合理的补法，或某种补法会改变实际行为时，把它作为契约候选交给用户裁决。

压缩、合并和抽象时检查事实、条件、程度、范围、优先级、例外与行动后果能否从新文本中准确恢复。只看到优化后产物及真实上下文的读者，如果可能形成与原意不同但表面合理的理解，就恢复必要语义或显式关系。

语言强度应匹配规则的真实强度。作用域清楚、没有合法例外或违反代价不可接受时，可以使用“必须”“禁止”等绝对表达；存在合理弹性时，写明默认方向、偏离条件和裁决依据，不用含糊软词假装保留空间。需要机制保证的权限和安全边界不能只靠强硬措辞。

根据集合语义选择表达：封闭集合完整列举，开放类别使用生成性原则和明确的非穷举示例，可实例化结构使用角色清楚的参数。枚举在提供完整契约、不可推断事实、有限选择或高代价遗漏防护时有独立价值；不要让当前实例和扩展模式互相冒充。

## 认知组织

为文档选择能够解释大部分内容的主模型，例如对象关系、决策模型、状态变化、任务路由或输入到结果的路径。旧稿中的顺序不自动成为新结构；一个模型不足时，使用少量互补视图并说明关系。

说明、分析、规范和决策类的长段展开，优先在较早位置给出统摄后文的概念、结论、关系或核心问题，再展开理由、证据、条件和细节。认知锚点按内容块判断，不要求每段机械重复主题句，也不覆盖叙事、人格体验和有意递进的表达职责。

标题、段落和顺序应表达真实关系：

- 同层级遵循一致的组织逻辑，形成明确的并列、阶段、对照或其他同级关系；
- 子标题展开、分解或限定父标题承诺的主题，不跨出父级职责；
- 条件和例外靠近实际约束的内容，不集中堆入文末；
- 内容无法自然归位时重新检查主模型，不创建“重要说明”“其他内容”等容器标题；
- 层级标题默认不使用纯装饰性序号，顺序、稳定引用或目标格式需要时保留编号。

使用最能显式表达信息关系的形式：同构比较适合表格，同类项目适合列表，简单流转适合箭头，需要完整论证、限定或语气连续性的内容适合段落。不要为视觉丰富制造伪表格、碎片列表或掩盖分支的线性流程。

结构不追求表面完整，但允许结构先于内容存在。已经形成的问题槽位可以在设计稿中标为“待讨论”，已确认但尚未完成的草稿内容可以标为“待完善”，模板可以使用 `<document-type>` 等角色明确的参数。它们分别表达未决、未完成和待实例化，不能互相冒充，也不能让下游替用户填写无权决定的空白。

## 当前有效性与维护

正式正文应像从当前认识出发自然写成。认识变化时替换失效模型并重组相关内容；被否定方案、版本成长叙事、编辑说明和无运行价值的历史退出当前正文。历史只有在迁移、兼容、审计或理解过去本身会改变读者行动时才以明确身份保留。

优化文档集时，把目录、文件名、位置、链接和入口也视为表达结构。文件组织应反映职责、作用域、加载关系、事实权和维护边界；只有形成独立受众、加载、作用域、事实权或维护边界时才拆分文件。

可变化的同一事实尽量只有一个明确权威来源。其他文档优先引用、链接或从权威内容编译；受众差异、加载边界、可移植闭包、独立职责或固定版本快照要求重复表达时，可以保留有意投影，但不能让多个位置竞争当前真值。引用在目标环境中不可用时，不为形式上的单一来源牺牲文档可用性。

保留完成文档职责所需的全部内容，删除不产生理解、判断、行动或体验增量的内容。理由在帮助泛化、解释非直觉设计或阻止关键误判时保留；人格文档中的语气、意象和节奏也可能直接承担功能，不能用命题数量衡量价值。

根据根因选择保持、局部修补、结构重组或整体重写。修改完成后，只依据新产物和目标读者真实可见的上下文复核：

- 当前意图、已确认契约和实际正文是否一致；
- 新建议是否被误写成用户已经确认的决定；
- 认知主线、层级和表现形式是否表达真实关系；
- 压缩、补充和重写是否造成理解漂移；
- 文档集的入口、事实权和维护关系是否清楚；
- 新内容以后能否自然归位，而不继续累积补丁。

这些是内部判断视角，不是固定输出清单。审阅任务先给结论和最重要的证据；修改任务说明实际改变、验证结果及仍需用户裁决的契约候选。
